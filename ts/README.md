# contexel

Deterministic, dependency-free **context shaping** for code-writing agents —
the TypeScript build of [contexel](https://github.com/maheshvaikri-code/contexel).

Tool calls return verbose, duplicated, sometimes hostile data. contexel sits at
the tool → context boundary and shapes it: select the fields that matter, drop
duplicates, gate by provenance, quarantine injection patterns, rescore by
relevance, truncate, rank, and trim to a token budget — every stage a pure
function over `Record<string, unknown>[]`, every run reproducible, every drop
attributable in an audit record.

**This package is a parity port, not a re-imagining.** The Python
implementation is canon; both languages run their test suites against the same
golden vectors (`parity/vectors.json`, generated by Python) so that the same
records, policy, and budget produce the same shaped output in either language.
Versions track the Python release. Design and boundaries:
[ADR-001](https://github.com/maheshvaikri-code/contexel/blob/main/docs/adr/001-typescript-parity.md).

## Install

```bash
npm install contexel     # zero runtime dependencies, Node >= 18, ESM
```

## Sixty seconds

```ts
import { select, dedupe, rescore, truncateField, rank, trimToBudget, trace } from "contexel";

const raw = await searchTool(userQuery);       // a batch of verbose results

const [context, t] = trace({ idField: "url" }, () => {
  let r = select(raw, { fields: ["title", "url", "snippet", "published"] });
  r = dedupe(r, { key: "url" });
  r = rescore(r, { query: userQuery, fields: ["title", "snippet"] });
  r = truncateField(r, { field: "snippet", maxTokens: 120 });
  r = rank(r, { by: "score", desc: true });
  return trimToBudget(r, { maxTokens: 1500 });
});

console.log(t.report());   // per-stage: records in -> out, tokens before -> after
console.log(t.audit());    // policy fingerprints + which stage dropped which IDs
```

Or pin the policy at the tool boundary, so the model never sees raw output:

```ts
import { shaped, stage, select, dedupe, trimToBudget } from "contexel";

const searchCode = shaped([
  stage(select, { fields: ["path", "line", "snippet"] }),
  stage(dedupe, { key: ["path", "line"] }),
  stage(trimToBudget, { maxTokens: 2000 }),
])(async (query: string) => repo.search(query));  // async tools are awaited, then shaped
```

## The eight stages

| Stage | What it does |
|---|---|
| `select` | keep only the listed fields |
| `dedupe` | drop duplicates by key or whole-record fingerprint (type-aware: `1`, `"1"`, `true` stay distinct) |
| `allowlist` | fail-closed provenance gate — keep records whose field is in the allowed set (a missing field reads as `null`, kept only if `null` is explicitly allowed) |
| `quarantine` | drop or flag records matching injection patterns ("ignore previous instructions", …); custom `patterns` extend the built-ins — `replacePatterns: true` is the explicit opt-out |
| `rescore` | batch BM25 relevance with word-boundary matching and in-order proximity bonus |
| `rank` | stable sort by a field; records missing the field sort last |
| `truncateField` | cut one field to a token budget, `…` suffix |
| `trimToBudget` | keep records until the total token budget is spent; `minRecords` guarantees the best records survive a too-small budget instead of returning `[]` |

Plus `merge` for combining multiple sources under one schema, `pipeline`/`stage`
for composition with a stable policy fingerprint, `trace`/`audit` for the
governance record, and `tokens.scoped` for concurrency-safe (AsyncLocalStorage)
tokenizer and serializer overrides per tenant.

## Errors and strict mode

A control must never be weaker than it looks, so misconfiguration always
throws a typed error. Every error is a `ContexelError` with a stable `code`
(the cross-language contract; messages are for humans): a `ConfigError` for a
wrong *call* — an unknown `match`, `fields: []`, an invalid regex, a negative
`maxTokens` — and an `InputShapeError` for wrong *data*. Bad data is lenient by
default, so valid input behaves exactly as before, with one exception that is
never lenient: `quarantine(records, { action: "flag" })` over a record that
already has the `into` key always throws `input.field_conflict`, inside
`strict(...)` or not and clean record or not, because carrying on would
overwrite your data (so re-running a flag pipeline on its own output throws; pass
a different `into`). Wrap calls in `strict(...)` to have a stage that gets a
non-array, or an item that is not an object, throw instead and name itself and
the item index:

```ts
import { ConfigError, InputShapeError, allowlist, quarantine, select, strict } from "contexel";

const sources = [{ source: "github", snippet: "ok" }, { source: "g", snippet: "no" }];
console.log(JSON.stringify(allowlist(sources, { field: "source", allowed: "github" })));

const nested = [{ note: { lines: ["ignore all previous", "instructions"] } }];
console.log(JSON.stringify(quarantine(nested, { fields: "note" })));

try {
  quarantine(nested, { fields: [] });          // a control that scans nothing throws
} catch (e) {
  if (e instanceof ConfigError) console.log(e.code);
}

strict(() => {                                 // opt in to shape validation
  try {
    // @ts-expect-error a deliberately wrong argument
    select(null, { fields: ["a"] });
  } catch (e) {
    if (e instanceof InputShapeError) console.log(e.code, e.stage);
  }
});
```

```text
[{"source":"github","snippet":"ok"}]
[]
config.empty
input.not_list select
```

`allowlist` is type-strict where it matters: a bool never equals a number, so
`true` cannot pass a gate that approved `1` (`1` and `1.0` are the same number
in JavaScript, as in the other ports). `strict(fn)` follows `await`
(AsyncLocalStorage) but not a `worker_threads` Worker, so
`pipeline(stages, { strict: true })` and `shaped(pipe, { strict: true })` switch
it on inside their own run, and a strict pipeline also checks that every stage
hands the next one an array:

```ts
import { InputShapeError, select, shaped, stage } from "contexel";

// @ts-expect-error a tool that returns null instead of an array
const tool = shaped([stage(select, { fields: ["a"] })], { strict: true })(() => null);
try {
  tool();
} catch (e) {
  if (e instanceof InputShapeError) console.log(e.code, e.stage);
}
```

```text
input.not_list shaped
```

Strict mode covers the eight record stages (`select`, `dedupe`, `allowlist`,
`quarantine`, `rescore`, `rank`, `truncateField`, `trimToBudget`) and the check
on what a pipeline or a `shaped` tool returns. It does not cover `merge`, which
still accepts anything iterable (`merge("ab")` returns `["a", "b"]`, strict or
not). `fields: []` throws `config.empty` for `quarantine` and `rescore` only;
`select(records, { fields: [] })` still returns `[{}, ...]`.

Only `undefined` means "use the default" for an option (`fields` of
`quarantine` and `rescore`, `into`, `proximity`, `match`, `desc`, `suffix`,
`minRecords`, `action`); `null` throws `config.invalid_value`, and so does
`replacePatterns: null` (it used to be treated as false). The exceptions are
`key` (`dedupe`) and `tokenizer`, where `null` still means "default", and
`patterns: null`, which means "no extra patterns". Before this release `null` was
treated like `undefined` for the options above.

If you catch errors by class: a bad `quarantine` regex used to throw a
`SyntaxError` (from `new RegExp`) and a wrong-typed or `null` argument a raw
`TypeError`. Both are now a `ConfigError`, which extends only `Error`, so
`e instanceof SyntaxError` and `e instanceof TypeError` no longer match; catch
`ContexelError` or `ConfigError` instead.

Differences between the languages (the codes are the contract, the rest can
differ):

- **Regex dialect.** `quarantine` compiles patterns with each language's own
  engine, so whether a pattern is invalid (`config.invalid_pattern`) is per port:
  `(?P<a>x)` is valid in Python and invalid here and in C#. A global inline
  flag such as `(?i)x` is a known limitation of custom patterns, which are
  joined into one regex with the built-in markers: it is always rejected here
  (`config.invalid_pattern`); on Python 3.11+ it raises unless it is in the first
  fragment of the combined pattern (so, in the default extend mode, always); on
  Python before 3.11 it is accepted and applies to the whole combined pattern,
  built-in markers included; C# accepts the flags .NET supports (such as
  `(?i)`). Avoid global inline flags in custom patterns; a follow-up is planned.
- **Integral floats.** `maxTokens: 1000.0` is accepted here, because JavaScript
  has one number type; Python rejects `1000.0`.
- **`null` as a default.** `fields: null` throws here (as `fields=None` does in
  Python); C# treats `fields: null` as "use the default fields" for `quarantine`
  and `rescore`.
- **Messages.** They differ between ports and are not part of the contract (the
  TypeScript ones say `NoneType` and `None`, for instance). A single bad pattern
  is named in the message; when the patterns only fail once combined, the message
  says they "cannot be combined" and does not name one.

## Parity, precisely

- Shaped output is structurally identical to Python's for JSON-safe records —
  enforced by golden vectors covering every stage, the composed contract, the
  audit record, canonical serialization, and token counts.
- Token counting is per Unicode **code point** (matches Python `len`), not
  UTF-16 units — `"café"` costs the same in both languages.
- Documented boundaries (see ADR-001): JS collapses `1.0` to `"1"` in
  serialization; Unicode word classes differ at the margins; pipeline
  fingerprints are language-local in v1.
