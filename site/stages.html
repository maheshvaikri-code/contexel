Stage reference

Every record stage: (records, **params) → records over plain list[dict], deterministic, non-mutating, auto-traced when a trace() is active. The entry and exit points as_records (payload → records) and join (records → string) are not that shape. Contract, not implementation — inputs, outputs, and the invariants held.

select(records, fields)

Keeps only fields on each record, in keep-list order. Missing fields are simply absent (no error, no None padding). Lossless: the dropped tokens were fields you were never going to use. Also the stage that makes rows uniform — which downstream table encodings reward. Everywhere a stage takes fields, a bare string names one field (fields="snippet" ≡ fields=["snippet"]) — it is never iterated as characters.

dedupe(records, key=None)

Drops duplicates, first occurrence wins, order preserved. key=None compares whole records (key-order insensitive); a field name or list of names compares those fields. Fingerprints are type-qualified — 1, 1.0, True, "1" are four different values — with a canonical-JSON fallback for unhashable values.

allowlist(records, field, allowed)

Provenance gate. Keeps only records whose field value is in allowed; records missing the field, or carrying an unhashable value, are dropped — fail closed. The strongest injection control a shaper can offer is refusing content from sources you did not approve: apply this first, before any relevance logic, so untrusted records never compete for the budget. Dropped records appear in the trace/audit with this stage as the reason.

A bare string for allowed is one allowed value (allowed="github" never admits "g"). Matching is type-strict where it matters: a bool never equals a number, so True cannot pass allowed=[1] and 1 cannot pass allowed=[True]; 1 and 1.0 still compare equal, because TypeScript cannot tell them apart. A wrong-typed allowed, or an unhashable entry in it, raises ConfigError.

quarantine(records, fields=("snippet",), patterns=None, action="drop", into="quarantined", replace_patterns=False, normalize=None)

Injection tripwire. A deterministic, case-insensitive pattern screen over the given text fields for the crudest prompt-injection markers — "ignore all previous instructions", role resets ("you are now"), system-prompt tags. action="drop" removes matches (audited); action="flag" keeps everything and writes a boolean to into so downstream policy decides. normalize="nfc" also scans the text in its Unicode NFC form and flags a record if either form matches, so it can only widen detection; it never touches the patterns. The default normalize=None scans the text as it is; any other value than None and "nfc" raises ConfigError. Cost: NFC takes time that grows with the square of a long run of alternating combining marks (seconds for 128,000 of them), so cap the size of text you do not control before you pass normalize="nfc".

Custom patterns extend the built-in list — passing your own domain markers can never silently disable the "ignore all previous instructions" detection (a configured-looking call that weakens the control is the failure mode this API refuses to have). Replacing the built-ins is an explicit opt-in: replace_patterns=True, and an empty replacement raises. A field whose value is a dict or list is scanned through every depth (keys and leaves, joined by spaces; strings as they are, numbers, booleans and None as their text), so a marker split by a newline inside a nested value is still found. fields=[] and an invalid regex (the error names the pattern; every custom pattern is compiled and matched on its own) raise ConfigError instead of leaving a control that quietly does nothing, and flag mode over a record that already has the into key raises InputShapeError (input.field_conflict) rather than overwriting it. Patterns are regex fragments; one classic pitfall — \b before a non-word character never matches, so \b\.env\b is dead: screen for .env-style tokens with (^|[\s"'([/])\.env\b (the / matters — paths like config/.env are the common form).

Honest scope: not a security boundary. A paraphrased attack passes; a benign document quoting an attack trips it. allowlist by provenance is the stronger control — this one makes the loud, literal cases visible instead of letting them compete silently. The three language ports do not catch exactly the same obfuscations (zero-width characters, homoglyphs and several others pass in all of them); the known limits are listed in the changelog.

rescore(records, query, fields=("snippet",), into="score", proximity=True, match="word", normalize=None)

Writes a deterministic lexical relevance score to into on a copy of each record, so ranking stops inheriting the search tool's score quality. BM25-style, computed inside the batch:

  • per-term IDF ln((N−df+0.5)/(df+0.5)+1) — rare terms weigh more;
  • saturating term frequency tf/(tf+1.5) — covering all the query's terms beats repeating one;
  • match="word" (default) counts exact word occurrences the way BM25/Lucene tokenize — value ≠ values, underscores split snake_case; match="substring" is the forgiving, decoy-prone alternative; match="stem" reduces every word of the query and of the text to its stem first, with a small frozen English suffix stemmer, so parse, parses, parsed and parsing are one term (the rule table is docs/stemmer-rules.md; English only, not a lemmatizer: configure and config stay apart); any other match raises ConfigError; fields=[] raises too;
  • normalize="nfc" applies Unicode NFC to the query and the text before they are lower-cased, so café typed as one character and as e plus a combining accent match each other; the default None changes nothing, any other value raises ConfigError. Each runtime ships its own Unicode database: the shared vectors use text that normalizes the same in all of them. Cost: NFC takes time that grows with the square of a long run of alternating combining marks (seconds for 128,000 of them), so cap the size of text you do not control before you pass normalize="nfc";
  • proximity=True: consecutive query terms in order within 80 characters earn a bonus — the source a query was phrased from usually carries its terms in sequence.
Lexical by construction: synonyms and paraphrase are invisible to it. When you need semantic relevance, put a model reranker in front — this stage removes the need to trust a tool's score, not the value of semantics.

rank(records, by, desc=True)

Sorts stably by a field name or key function; records missing the field go last. Run it before trim_to_budget so the budget drops the least important records, not arbitrary ones. Values of by must be mutually comparable.

truncate_field(records, field, max_tokens, tokenizer=None, suffix="…")

Clips one long text field to the longest prefix that fits the cap, then appends the suffix. For the built-in estimator the cut is closed-form (ceil(len/4) is invertible: n tokens hold at most 4n characters, so the prefix is four characters per token left after the suffix); for custom tokenizers it binary-searches. Non-string values pass through untouched. Never exceeds the cap.

trim_to_budget(records, max_tokens, tokenizer=None, min_records=0)

Keeps the greedy prefix that fits the budget: each record costs the token count of its serialized text plus 2 for list framing; the walk stops before the budget is crossed. Assumes records are already ordered by importance. If even the first record exceeds the budget the result is empty — run truncate_field first for oversized records, or set min_records: the first that-many records (the best ones, post-rank) are kept even over budget, so a too-small budget can never return an empty list that reads as "nothing matched". The overrun stays visible in the trace/audit token counts.

merge(*sources, schema=None, dedupe_key=None)

Unifies differently-shaped tool outputs into one record shape. schema maps a unified field name to a source field name or a list of candidates tried in order; dedupe_key optionally dedupes across the merged result. With schema=None the sources are concatenated unchanged. A combiner rather than a single-collection transform — the one stage that is not auto-traced.

merge(web, docs, schema={"title": ["title", "name", "headline"],
                         "url":   ["url", "link", "href"]})

as_records(x, field="text")

Turns a payload into records, the shape every other stage takes, so a log, a web page or a plain string can go through dedupe, rescore, rank and trim_to_budget. A string becomes [{field: x}]; a mapping becomes [x] (the same object); a list keeps each mapping item and wraps every other item as {field: item} (nested JSON values are fine). None, bytes and every other type raise input.not_list, and field must be a non-empty string. An entry point, like merge: call it outside pipeline; it is not auto-traced and it checks its input in every mode, not only in strict mode.

split(records, field="text", by="lines", size=None, into="chunk")

Cuts the text in field into chunk records. A chunk is a copy of its parent record with the text replaced and {"index", "start", "end"} stored under into: index counts from 0 within the parent and [start, end) are code-point offsets, so text[start:end] is the chunk. Every chunk keeps its trailing separator, so joining the chunks with "" returns the text exactly.

  • by="lines": a chunk ends after each \n (\r\n is one boundary, a lone \r is none, and Python's wider splitlines set is not used).
  • by="paragraphs": after each run of two or more newlines, (?:\r?\n){2,}.
  • by="size": every size code points; size is a required positive integer here and an error with any other mode (config.contradictory).

The boundaries are the same in Python, TypeScript and C#. A record whose field is not a string passes through; an empty text produces no chunks, so that record disappears; a record whose text is a string and that already has the into key raises input.field_conflict. Unlike the original stages it checks its input in every mode: a non-list raises input.not_list, a non-mapping item input.not_mapping. It is auto-traced and keeps every id, so under trace(id_field=...) an empty-text record that vanishes is reported as dropped and a chunk dropped later is reported under its parent's id. That is exact per distinct id value: with duplicate ids a record that vanished can be hidden by a sibling's chunks of the same id, and an id_field that is the split field itself is rewritten by the split, so a parent cut into several chunks is reported dropped. rank reorders chunks by score: to restore reading order before join, rank again on the offset with a named key function (by=lambda r: r["chunk"]["start"], desc=False). Overlapping windows and token-sized chunks are not offered.

chunks = split(as_records(log), by="lines")
text = join(chunks)                  # == log, byte for byte

join(records, field="text", sep="")

Turns records back into one string. A record without field is skipped; a string value is used as it is; any other value is rendered the way the token budget priced it (tokens.serialize); the parts are joined with sep. An exit point, like merge: call it outside pipeline (a strict pipeline rejects a stage that returns a string, naming it); it is not auto-traced and it checks its input in every mode.

pipeline · stage · shaped · trace · tokens

  • pipeline([...]) — plain left-to-right function composition; any records → records callable (even a lambda) is a valid stage, so you can drop to code for anything irregular and still breakpoint inside it. pipeline([...], strict=True) runs every stage in strict mode and checks each stage hands the next one a list.
  • stage(fn, **params) — binds keyword args so a stage slots into a pipeline.
  • @shaped(pipe) — runs a tool's record-list return value through a pipeline before it returns; the model never sees raw output. Async tools work too: a coroutine function is awaited, then shaped. @shaped(pipe, strict=True) also requires the tool to return a list.
  • pipeline([...]) exposes .fingerprint — a stable policy hash of stage names and bound parameters (a set by its sorted contents, a nested pipeline used directly as a stage by its own fingerprint, a tiktoken tokenizer by its encoding), recorded into any active trace so an audit can say which policy version shaped a context. For the exact containers it copies, the fingerprint cannot go stale: stage() keeps a private copy of the exact lists, tuples, dicts and sets bound to it (not of a container subclass or a custom object, nor of the elements of a TypeScript Set; C# copies no bound parameter).
  • trace(id_field=...) — context manager; every stage records records-in/out and tokens-before/after, and with id_field also which records each stage dropped (records lacking the field are untracked). t.audit() emits the JSON-able governance record. Inactive overhead is a single ContextVar lookup per stage. The benchmark suite times the full contract over 10,000 records with tracing inactive and with it active (the Tracing overhead row on the benchmarks page, generated from benchmarks/RESULTS.json); it does not time an untraced baseline. Active tracing token-counts every stage boundary and is priced accordingly.
  • tokens — count, use_tiktoken() (exact where tiktoken covers the model), tiktoken_tokenizer(), set_tokenizer(fn), set_serializer(fn), serialize(value), and scoped(...) — a context-local overlay that isolates concurrent tenants. Strings always bypass the serializer.

Errors and strict mode

Every error contexel raises on purpose is a ContexelError with a stable code — the cross-language contract; messages are for humans and may differ between the Python, TypeScript and C# ports.

coderaised when
config.invalid_valuean unsupported option value or a wrong-typed parameter (match, action, by, a negative or non-integer max_tokens)
config.emptythe call would silently do nothing or everything: an empty pattern fragment, an empty replacement list, fields=[] for quarantine and rescore
config.contradictoryreplace_patterns=True without patterns, or size given to split with a by other than "size"
config.invalid_patterna pattern fails to compile; the message names the pattern
input.not_list(strict) records are not a list; split, join and as_records raise it in every mode
input.not_mapping(strict) an item is not a mapping; the message names the stage and index. quarantine always raises it, strict or not, because a screen that skips what it cannot read would keep the attack; split and join raise it in every mode
input.field_conflictan output field already exists: the quarantine flag into (always raised), or the split into when the record's text is a string — raised because continuing would destroy data

ConfigError is also a ValueError and InputShapeError also a TypeError (in C# both derive from ArgumentException). Handlers for the shape errors keep working, but a configuration mistake that used to raise a raw TypeError now raises a ConfigError, which an except TypeError no longer catches, and a bad quarantine regex raises ConfigError, not re.error. Configuration errors always raise. Data-shape errors are opt-in, with two exceptions: by default a stage keeps its lenient behavior, so valid input is byte-identical to before, but input.field_conflict and quarantine's input.not_mapping are raised whether or not strict mode is on. Strict mode covers the eight record stages and the pipeline or shaped output check, not merge; the payload stages (as_records, split, join) are new and check their input in every mode.

with contexel.strict():                         # ambient, this context only
    select(records, ["a"])                      # InputShapeError names stage + item

pipe = pipeline([...], strict=True)             # also checks every stage returns a list

@shaped([...], strict=True)                     # also requires the tool to return a list
def search(query):
    return repo.search(query)
with strict(): lives in a context variable: it follows await but a bare thread starts without it. pipeline(strict=True) and shaped(strict=True) enter strict mode inside their own run, so they hold on worker threads. Strict never changes a successful result and is not part of the fingerprint.
