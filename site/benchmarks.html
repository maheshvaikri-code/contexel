Benchmarks

Measured, not asserted — and deliberately without a headline "X% reduction" number, because reduction is a property of your data and your budget, not of the library. Two reproducible suites; full tables live in the repo (benchmarks/RESULTS.md, benchmarks/COMPARISON.md). Every number on this page is generated, or checked against the results: the tables are rendered from benchmarks/RESULTS.json and benchmarks/COMPARISON.json, and python tools/check_benchmark_numbers.py, run in CI, fails when this page disagrees with them.

How to read it

  • Two experiments in one table. ms @28k holds the policy constant — libraries get identical hand-written glue for whatever they lack, so timing differences are theirs. The outcome columns (Recall / Compliance / Useful) are the opposite: each library acts only through its own operations, so they show what each one actually ships. Native ops are computed from the code that defines each implementation, not typed.
  • Recall with zero compliance is not recall. toolz and llama-index keep the needed record by emitting many times the budget (the Fill column) — a context no window accepts. langchain-core holds the budget but, with no projection or dedupe, fills part of it with bloat and the needed record survives only when it happens to arrive early.
  • contexel's ms/episode is the work, not overhead. It and the hand-written term-overlap scorer are the two slowest budget-compliant rows, in an order that can change from run to run: contexel derives relevance from each record's own text (batch relevance with IDF, saturating term frequency and in-order proximity) on top of projecting, deduping on a key, clipping, ranking, and budgeting stage by stage, and the scorer does less of that record work (whole-word overlap). Both clip and price with the same estimate: contexel computes every cap with the active tokenizer, here the default of about four characters per token. Every other compliant row is faster by doing less still. All rows are noise next to one model call. The timing columns (the ms columns and Import ms) are one run of the command on one machine, and vary with the machine's load and from run to run; the other columns are deterministic.
  • The two recall columns bound the semantic concession. The hand-written row trusts the tool's score, so its recall tracks that score's quality. contexel's rescore derives relevance itself, so its two columns read the same — on these episodes. The hand-written row with its own term-overlap scorer is the fairest comparison: another rescorer, not none.

Inflected queries

The episodes above query with the target's own words, so exact-word matching is never tested. A second set of episodes, chosen so that every query term can be inflected, hands the shaper deterministic inflections of those words (parse becomes parsing, returns becomes return; synthetic, the rule is in benchmarks/inflection.py), while its hit lists come from the original terms. Its target records differ from the main table's, so contexel's recall with the original terms there need not equal its recall in the main table. Exact-word matching fails by construction and match="stem" is measured (only terms the frozen stemmer maps to one stem are used, so the stem row shows the stem match carrying through ranking and the budget, not how many English inflections the stemmer covers):

Exact-word matching (the default) collapses on inflected queries, and so does the hand-written term-overlap scorer; match="stem" recovers them (for the terms the stemmer maps to one stem, which is what the episodes use). The hand-written row that trusts the tool's score never reads the query, so inflection cannot touch it: it is the control. This measures inflection robustness only — not synonyms, not paraphrase, not meaning.

Limits, stated plainly

Recall@budget has a ceiling no shaper escapes: when a query legitimately describes more records than the budget holds, some valid record is cut — semantic or not. Full recall here means the ambiguity clusters resolved once exact-word evidence was used; vaguer queries, a different corpus, or a tighter budget can put it back below full recall, and that is the data's property, not the policy's.

rescore is lexical: a query saying parsing scores zero against a document saying parse unless you opt in to match="stem", a small frozen English stemmer; synonyms and paraphrase belong to semantic rerankers (LLMLingua, ColBERT, cross-encoders), which contexel deliberately does not compete with.

And shaping is not an injection defense: rescore ranks textual relevance — a hostile record that matches the query well ranks well, including one that says "ignore all previous instructions". contexel ships two deterministic boundary controls — allowlist (a provenance gate, the strong control) and quarantine (a pattern tripwire for the loud, literal cases; paraphrase passes it) — both traced and audited. Content authentication still belongs upstream of the contract; treat every shaped record as data, never as instructions.
