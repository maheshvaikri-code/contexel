# Benchmark claims, phase 1: correct what is wrong or misleading, change no measurement — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every comparative statement and every benchmark number in the README, the PyPI README, the site and the benchmark reports is true, fairly worded and traceable to generated results, after an independent audit found that the numbers reproduce but several statements about the compared libraries, and the reading of the competitor rows, do not hold.

**Architecture:** Text and rendering only. The audit reports (filed in Task 1) are the spec: each finding has an id (N1, F6, D2, ...), a location, a verdict and a proposed wording. This plan fixes the scope per file, the rulings that override or choose between proposals, and the checks. **No measurement is re-run and no published number changes** except that the Compliance column leaves every published table (ruling P1-1). Everything that needs a new measurement is phase 2 (the last section).

**Tech Stack:** Python 3.9+ standard library (the renderer `benchmarks/publish.py`, the report templates in `benchmarks/competitors.py` and `benchmarks/suites_report.py`, the checker `tools/check_benchmark_numbers.py`), pytest, Markdown and static HTML. No new dependency.

**Spec:** `docs/reviews/benchmark-claims-audit-facts.md` (third-party statements and fairness, ids N, F, D, X, I, S, C) and `docs/reviews/benchmark-claims-audit-numbers.md` (reproduction and numbers, defects D1 to D20 in its section 7, unchecked claims in its section 8). Do not confuse the two id spaces: the facts report's `D1` to `D3` are dependency and import rows; the numbers report's `D1` to `D20` are its ranked defects. Cite them as `facts:D1` and `numbers:D1`.

**Baseline (verified before the plan):** `main` at `1825844`; `python tools/check_benchmark_numbers.py` passes; the audit reproduced every non-timing number (three runs of `python -m benchmarks.competitors`, two of `python -m benchmarks`).

## Global Constraints

- **No measurement changes.** Do not run `python -m benchmarks`, `python -m benchmarks.competitors` or anything that rewrites `benchmarks/COMPARISON.json` or `benchmarks/RESULTS.json` (the committed timings would change). Regenerate the marked blocks and the two Markdown reports from the committed JSON only: `python tools/check_benchmark_numbers.py --write`, then `python tools/check_benchmark_numbers.py`. The JSON files are not edited by hand and do not change in this plan.
- **No new number appears in prose unless the tooling generates it or it is already generated.** The audit measured extra figures (contexel 95% with `proximity=False`; 99.5% vs 98.4% over ten seeds; 94 of 100 contexts over 1,500 cl100k tokens; toolz 4/6 with `topk` and `accumulate`; langchain-core 78% with strong-ordered input; llama-index-core `ChatMemoryBuffer` 1/6, 30%, 69%). They are true as measured but nothing in the repository generates them, so phase 1 words them qualitatively ("a different wiring changes these rows", "the lead comes partly from the in-order proximity bonus") and phase 2 generates them.
- **Neutral, precise wording.** Library names with their own capitalization (LangChain, LlamaIndex, Haystack, toolz); a statement about a library names the module or function it is about; no adjective that scores a project ("poor", "bad"); every claim about what a library "does not do" says "in the wiring this benchmark chose" where that is what was measured. Do not weaken a true statement to be polite and do not delete a true limitation.
- **Public repository:** no Windows user name, home or temporary path, e-mail address or agent identifier in any file or commit message. This machine writes CRLF: preserve each file's existing line endings (read diffs with `git diff --ignore-cr-at-eol`).
- **No version bump, no release.** The CHANGELOG entry goes under `[Unreleased]`. `README_PYPI.md` changes reach PyPI only at the next release.
- **One commit per task**, Conventional Commits, 72 characters at most, **no `Co-Authored-By` trailer** (the project owner's standing rule, which overrides the harness default). Never push, open a pull request or merge: those are the human's.
- Tests are never weakened to go green; a test that pinned the old wording or the Compliance column is updated to pin the new text and the reason is stated in the commit body.
- If a finding cannot be fixed by wording (it needs a measurement), **leave the text qualitative, record the finding under "Phase 2" in the master plan, and do not invent a number.**

## Rulings made at plan time (open to the human's correction)

- **P1-1. The Compliance column leaves every published table** (README.md, README_PYPI.md, site/index.html, site/benchmarks.html, `benchmarks/COMPARISON.md`) and every sentence that rests on it (the human's decision, 2026-11-27: "Drop the column"). The harness keeps computing `compliance_pct` and the JSON keeps it (the results file is a record, and the checker's data model uses it); only rendering and prose change. **`Fill ×` stays**, relabelled "Fill × (estimated tokens ÷ budget)": it is the same estimator-based quantity and the only column that shows that two rows emit far more than the budget. Do not add an exact-token (cl100k) column (the human declined it). Cost if wrong: one column fewer; reverting is a rendering change.
- **P1-2. The estimator is stated once, plainly, where the budget is introduced and in the limits paragraph:** every budget in the benchmark is counted with contexel's default estimator (about four characters per token), the same one the hand-written glue uses; the estimator is for soft budgeting and a hard limit needs an exact tokenizer (`contexel[accurate]` and `tokens.use_tiktoken()`, or the provider's own counter). Say that contexts measured in exact tokens run over the estimated budget, **without a number** (phase 2 generates it). Sentences "holds a 1,500-token budget in 100% of episodes" and "the only row with full marks" are rewritten to claims that remain true without the column (audit facts:F6, facts:S1, numbers:D2).
- **P1-3. "Native ops" is relabelled, not recounted.** The counts (6/6, 0/6, 2/6, 1/6, 0/6) stay as generated; the text says they are counted over the step lists chosen in `benchmarks/competitors.py` ("in the wiring this benchmark chose"), that which library functions each row uses and which operation each step serves are the author's choices, and that other wirings exist (name toolz `topk`/`accumulate`, llama-index-core metadata exclusion, ingestion dedupe and `ChatMemoryBuffer`, without counts). Remove "computed, not typed" in the strong form (facts:N1, N2, N5, N7, numbers:D6).
- **P1-4. The LlamaIndex statements are made consistent** (facts:N3, N4, F4): one description everywhere ("related operations on its node types: a score cutoff, a score-ordered reorder, rerankers with `top_n`, metadata exclusion, docstore dedupe, `PromptHelper` truncation, a `ChatMemoryBuffer` token limit; this benchmark wires two of them and counts neither as one of the six stages"), the false "not bounding them" removed, and the fact that the 2.0 cutoff removes nothing under the strong signal stated.
- **P1-5. Disclosure is added once per surface, in the same words:** "This benchmark was written by contexel's author. The comparison wirings are our best effort, one dataset, 100 episodes; corrections from the maintainers of the compared libraries are welcome (open an issue)." (README.md benchmark section, README_PYPI.md, site/benchmarks.html, site/index.html near the table, `benchmarks/COMPARISON.md` header) (facts:C1, C2). The issue link is `https://github.com/maheshvaikri-code/contexel/issues`.
- **P1-6. ISON:** wherever ISON is recommended or measured, add "(ISON is by the same author as contexel.)" (README.md, README_PYPI.md, RESULTS.md suite 6, site/index.html, site/architecture.html, site/getting-started.html, the site footer) (facts:I1). Suite 6's comparison text says it is against contexel's default spaced JSON and that any header-plus-rows encoding avoids repeating keys (facts:I3); the compact-JSON and CSV rows are phase 2.
- **P1-7. Third-party statements follow the audit's proposed wording** unless it contains a number that nothing generates: facts:X1, X2, X3 (rename the Haystack row to name `DocumentJoiner`, `MetaFieldRanker`, `LostInTheMiddleRanker` and say what each does), X5 (Anthropic programmatic tool calling and code execution with MCP; Cloudflare Code Mode in the Agents SDK ship the mechanism; the model writes or saves the shaping code; contexel supplies vetted, versioned stages), X6 (state "not on PyPI as of 2026-11-26" with the command, name `context-kit` and `ctxeng` as other standalone libraries that were not benchmarked, and drop "prior-art claim did not verify" unless the review is named), X7, X8, X9 (split the LLMLingua row from the ColBERT and cross-encoder row), X10, X11.
- **P1-8. Superlatives are replaced by the evidence-sized claim:** "proven" becomes "tested" (facts:S2, S3), "Measured, not asserted" is kept only where every claim under it is measured (S4), `select` "the fastest lossless cut" becomes "a cheap lossless cut" (S8), "real, public data ... genuine duplicates" says the searches are simulated (S5), recall is not highlighted as best on a row whose Fill is far above 1 (S9), unmeasured assertions are labelled as claims (facts:F9, F10, numbers:D17).
- **P1-9. Reproducibility text:** the benchmarks extra stays unpinned in `pyproject.toml` (an extra is not an exact pin), and a constraints file `benchmarks/constraints.txt` records the measured versions (toolz 1.1.0, langchain-core 1.4.9, llama-index-core 0.14.23, the versions in `COMPARISON.json`); the README says to install with `-c benchmarks/constraints.txt` to reproduce the measured versions (facts:C4). The Deps column is defined (transitive installed closure, no extras; direct requirements in a note only if generated, otherwise not) (facts:D1), "about 20 ms" import gets its qualifier (numbers:D8), `ms/episode` says the benchmark's own scoring is included (numbers:D7, without the unmeasured percentages), the `ms @28k` text says most of the langchain-core and llama-index-core time is converting records to the library's message or node type (numbers:D9), "−29%" says it is the synthetic sample (numbers:D10, without the 4% to 13% figures), dead references are fixed (numbers:D11), "Every number is generated or checked" says CI does not regenerate the results (numbers:D13), "genuine duplicates" says all but a few (numbers:D14 without the count 7 unless the audit's count is generated: it is not, so say "almost all"), numbers:D15 and D16 are reworded, numbers:D3 is fixed in `site/stages.html` (see Task 4).
- **P1-10. The checker's reach grows:** `benchmarks/publish.FILES` gains the site pages that carry benchmark or timing numbers (`site/stages.html`, `site/architecture.html`, `site/getting-started.html`, `site/contract.html`), so the audit's class of error (numbers:D3, section 8) fails CI; any finding this produces is fixed by wording, not by loosening the scan. If a page cannot be scanned without a false positive, **stop and report** the case instead of exempting it silently.
- **P1-11. Deferred to the site refresh after the release:** numbers:D20 ("Eight pipeline stages") and everything about unreleased features on the site; the phase-1 diff must not touch them.
- **P1-12. The proximity finding (numbers:D1) is disclosed qualitatively:** the text says the lead of contexel over the term-overlap baseline comes from `rescore`'s in-order proximity bonus (not "partly": the controller re-ran the audit's probe, the bonus reaches the target in 100 of 100 episodes and with it off contexel scores 95% against the baseline's 97%), that the episode queries keep the target's word order, and that with the bonus off contexel's recall on these episodes is not above the baseline's (this benchmark does not generate that row); the numbers and the proximity-off and multi-seed rows are phase 2. Amended at the Task 2 review. "Fairest comparison" stays only with that sentence next to it (facts:F8).
- **P1-13. Empty contexts (numbers:D4) are disclosed qualitatively** in the Useful % definition (a context that is empty counts as fully useful by the current scoring; langchain-core returns one when its first record alone exceeds the budget) with no new number; the scoring change is phase 2. Same for "recall is the same under both signals" (numbers:D5): state that it holds by construction because the two signals differ only in the score value and the hit order is the same.
