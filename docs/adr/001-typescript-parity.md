# ADR-001 — TypeScript parity package

**Status:** accepted · 2026-07-26 · Chief Architect

## Decision

1. **Same repo, `ts/` package**, published to npm as `contexel` (name
   verified free). Version tracks the Python package (starts 0.1.15).
   Zero runtime dependencies; devtooling = `typescript` + Node's built-in
   `node:test` only. Node ≥ 18 (uses `node:crypto`, `AsyncLocalStorage`).
2. **The parity contract is a golden-vector suite** (`parity/vectors.json`),
   generated by the Python implementation and asserted byte-identical by
   BOTH languages' test suites (contract-first per
   `skills/interoperability.md`: the vectors are the schema; the two
   implementations conform to it). Coverage: every stage, the composed
   contract, rescore scores, token counts, and the audit record.
3. **Canonical serialization is Python's**: the TS serializer replicates
   `json.dumps(..., sort_keys=True, ensure_ascii=False, default=str)`
   including `", "`/`": "` separators; token counting is per Unicode code
   point (not UTF-16 units).
4. **Documented parity boundaries (v1)** — stated, not hidden:
   - JS has one number type: a JSON `1.0` parses to `1` and serializes as
     `"1"` (Python: `"1.0"`). Parity holds for JSON data without
     integer-valued floats; the boundary is documented in both READMEs.
     (Same root cause: integers beyond 2^53 lose digits in JS.)
   - Non-integer floats serialize identically **including** Python's
     scientific-notation thresholds (`1e-05`, two-digit exponents) via a
     dedicated float formatter; `round()` replicates CPython's
     correctly-rounded half-to-even (vector-enforced, incl. the
     `2.675 -> 2.67` non-tie trap).
   - Non-string field values feed `rescore`/`quarantine` through a
     Python-`str()` replica (`None` -> `"None"`, containers via repr).
     Exact for ASCII and common text; Python's repr escapes for exotic
     non-printables (Cf/Zs beyond Latin-1) are a margin. Nested dicts with
     integer-like string keys may order differently (JS object key order).
   - `rescore` word matching uses `/[\p{L}\p{N}]+/gu` — identical to
     Python's `[^\W_]` on ASCII (all vectors); exotic Unicode word classes
     may differ at the margin. Match positions are code-point indices in
     both languages (UTF-16 offsets are converted).
   - `rank`/serializer key-sort compare strings by code point like Python;
     `rank` raises `TypeError` on incomparable values like Python, except
     lists (Python compares element-wise; TS raises) — a margin.
   - `allowlist` membership uses Python equality (`True == 1 == 1.0`);
     unhashable `allowed` entries raise, unhashable record values fail
     closed — all vector-enforced.
   - `quarantine` case-insensitivity: Python `re.IGNORECASE` Unicode-folds
     (`ſyſtem prompt` matches `system prompt`); JS `"i"` without `"u"`
     does not fold non-ASCII case pairs, so TS misses those evasions.
     Adding `"u"` would reject fragments valid only without it — margin
     stands until a folding fix; ASCII text behaves identically.
   - `round()` normalizes `-0` to `0` (Python can return `-0.0`, e.g. an
     audit `reduction` when tokens grow marginally) — same root cause as
     the int/float collapse above; visible only pre-serialization.
   - Pipeline fingerprints are language-local in v1 (Python `repr`
     replication is brittle); a canonical cross-language fingerprint is
     roadmap.
5. **`scoped` maps to `AsyncLocalStorage`** (callback style:
   `tokens.scoped({tokenizer}, fn)`) — the JS analog of contextvars, same
   isolation semantics for async tasks. `@shaped` improves on Python:
   a returned promise is awaited then shaped (JS can't reliably detect
   async functions statically, so it shapes thenables).

## Consequences

Parity is enforced by CI-runnable tests, not by review vigilance; any
divergence in shaping output across languages is a red build. npm publish
is a §5 human action; release automation for npm is a follow-up task.
