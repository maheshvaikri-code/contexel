# ADR-002 — C# parity package (NuGet)

**Status:** accepted · 2026-07-28 · Chief Architect

## Decision

1. **Same repo, `csharp/` directory**, published to NuGet as `Contexel`
   (ID verified free). Version tracks the Python package. Target
   `net8.0` (LTS); **zero runtime dependencies**; test project uses xunit
   (dev-only, same standing as the TS package's `typescript` devDep under
   the dependency policy). Local SDK verified: 8.0.403.
2. **The same golden-vector contract as ADR-001**: `parity/vectors.json`
   is generated by the Python canon; the C# test suite asserts against it
   (every stage, the composed contract, the audit record, canonical
   serialization, token counts, and the 15-class edge block). Any
   divergence is a red build; CI regenerates vectors from canon first.
3. **C# has a stricter parity envelope than TS** — .NET preserves the
   int/float distinction, so ADR-001 boundary 4a does NOT apply: a JSON
   `1.0` loads as `double` and serializes as `"1.0"` exactly like Python.
   The vector loader must therefore preserve int-vs-float from the raw
   JSON text (`System.Text.Json` `JsonElement.GetRawText()` decides
   `long` vs `double`), and the value model is
   `null | bool | long | double | string | List<object?> |
   Dictionary<string, object?>`.
4. **Culture invariance is a hard rule**: all formatting via
   `CultureInfo.InvariantCulture`, regex with
   `RegexOptions.CultureInvariant`, string ordering by **code point**
   (C# strings are UTF-16 like JS — `CompareOrdinal` has the same
   astral-plane ordering hazard the TS port fixed; the same
   code-point compare/indexer helpers are ported).
5. **Python-semantics helpers are ported from the TS `py.ts` design**
   (proven by 118k-case rounding fuzz + 50k-double serializer fuzz):
   `PyFloat` (repr thresholds, two-digit exponents), `PyRound`
   (correctly-rounded half-to-even; tie iff `x * 2^(nd+1)` is an odd
   integer), `PyStr`/`PyRepr` (None/True/containers), `PyEqKey`
   (True == 1 == 1.0; unhashable raises), code-point compare/indexer,
   Python `rstrip()` whitespace set.
6. **API shape**: static stage methods with C# named optional parameters
   (`Stages.Select(records, fields)`, `Stages.TrimToBudget(records,
   maxTokens, tokenizer, minRecords)`) — closer to Python kwargs than
   TS's params-object; PascalCase per .NET convention.
   `Tokens.Scoped(...)` uses `AsyncLocal<T>` (the .NET analog of
   contextvars; overlays merge so nesting composes). `Shaped` wraps
   sync and async tool delegates. Stable sorts via LINQ `OrderBy`
   (`List.Sort` is unstable — never used for ranking).
7. **Documented parity margins (v1)**:
   - Case-insensitive matching: `RegexOptions.IgnoreCase |
     CultureInvariant` uses .NET simple case folding; like JS (ADR-001),
     some non-ASCII folds Python catches (`ſ` → `s`) are missed. ASCII
     identical; margin stated, vectors are ASCII.
   - Exotic `repr()` escapes beyond Latin-1 inside nested containers —
     same margin as TS.
   - Pipeline fingerprints remain language-local in v1.
   - Integers beyond `long.MaxValue` (Python bigints) are out of the
     JSON-safe envelope; **within** it, equality/ordering are exact even
     past 2^53 (64-bit ids never collapse through double conversion —
     exceeds the TS port).
   - `round()` normalizes `-0` to `0` (Python can emit `-0.0` for an
     audit `reduction` when tokens grow marginally) — same margin as
     ADR-001; the ports agree with each other.
   - Lone surrogates (out of the JSON-safe envelope) advance one unit
     like Python's per-code-point strings — never a crash.
8. **Release**: NuGet publish rides the existing tag-gated pipeline as a
   `nuget-publish` job (needs `NUGET_API_KEY` repo secret — §5 human
   setup), gated on the 3-OS suites like npm, dry-run on dispatch,
   3-OS post-publish smoke. `csharp/` ships its own README; the version
   guard requires `Contexel.csproj` to equal the tag.

## Consequences

Three languages, one behavioral contract, enforced by the same
Python-generated vectors in CI. Each new language now costs mostly
mechanical porting: the hazard classes (floats, rounding, code points,
`str()` replication, stable sorts) were identified and vector-encoded
during the TS effort. The npm/TS boundary list shrinks for C# (int/float
preserved); the case-folding margin recurs.
