## Findings to fix

### A. Python property tests (tests/_gen.py, tests/test_properties.py)
- **I1 / F-6 (Important/Medium): rank stability and positional correspondence are unchecked.** `test_rank_is_a_permutation_and_stable` never compares equal-score ties with input order; a rank that breaks ties by `(r[by], str(r.get("path")))` passes every Python, TS and C# test (QA row 7). Also AC 20 says "order preserved where promised": `test_transform_stage_preserves_count` checks only `len`. Fix: tag each generated record with its input index (for example a `_i` field the stages keep) and assert (a) for equal scores rank output keeps ascending `_i`, (b) for the SAME_LENGTH stages output record i corresponds to input record i (compare a field the stage keeps; use `path`+`line`+`_i` or similar; `select` must keep what you compare).
- **I2 (Important): "each property has a canary" is claimed (spec section 8, test docstring, CHANGELOG) but only purity, determinism and idempotence have canaries.** Add a canary for EACH remaining check so the checker is shown to fail on a deliberately broken stage: subsequence (a stage that reorders its output must fail `is_subsequence`; be sure the helper's shared-iterator logic is really exercised), count (a stage that drops a record must fail the count check), positional correspondence (a stage that reverses output must fail it), the rank permutation/tie-stability check (a rank that breaks ties differently must fail), the trim-budget check (an over-budget list must fail it), and the new effect checks below. Keep the claim in the docstring/CHANGELOG TRUE after your change (re-read both and fix the wording if needed).
- **F-7 (Low): the filter-stage properties are satisfied by a no-op** (a dedupe that never dedupes passes all of them, QA row 49). Add effect assertions: after `dedupe_key` no two output records share `(path, line)`; after `dedupe_whole` no two outputs are equal; after `allowlist` every output `source` is in the allowed list; after `quarantine_drop` no output snippet contains the built-in marker phrase (the generator's WORDS already include "ignore all previous instructions"), and `quarantine_flag` marks every such record `True`.
- **M3: "Failures print the seed" (AC 20) holds only for assertion failures.** If a stage raises inside a seed loop the traceback has no seed. Wrap each per-seed body (a small helper or context manager) so ANY exception is re-raised with the seed in the message (chain with `from`); Python 3.9 compatible (no `add_note`). Prove it with a test using a stage that raises.
- **F-10 / QA row 1: the generator emits a fixed key set,** so a stage that mutates only an unexpected key (row 1: `r.pop("junk", None)` on select input) survives. Add random extra keys to the generated records (for example a `junk` key with varied values and one or two `extra_<n>` keys on some records) so such mutations are caught. Re-confirm goldens are unaffected (they do not use the generator).
- **M6: naming/citation nits.** `test_trim_min_records_keeps_the_best_records` checks that a prefix is kept, not "best": rename accurately. The IDEMPOTENT comment cites ADR-003 for `input.field_conflict`, but ADR-003 never mentions it: cite the design spec's error table and brief AC 5 instead.

### C. Parity cases (parity/parity_cases.py, tests/test_parity_cases.py; vectors regenerate)
The TS and C# runners are generic, so new cases are replayed there automatically. Add cases so that EACH of these mutants fails in ALL languages where it exists (QA mutation table, rows in brackets):
- **F-1:** `merge` "first present candidate wins" [rows 33, 39, 42]: add a record that carries TWO candidate names with different values (for example both `title` and `name`), so removing the `break` changes the result.
- **F-2:** `truncate_field` must discriminate code points from bytes AND from UTF-16 units [rows 24-26, 32, 41]. The existing case's inputs exceed the budget under every counting rule. Add inputs that are WITHIN budget by code points but over budget by bytes (for example 12 CJK characters at max_tokens=4) and by UTF-16 units (astral characters, for example emoji, sized to straddle the boundary), plus one that is over budget. The heuristic is `ceil(len/4)` per count; reason about each input carefully and show, in your report, the per-counting-rule token counts that make each case discriminate. Keep case data inside the parity envelope.
- **F-4:** `quarantine` must scan multiple fields [rows 22, 30, 37] and be shown to drop/flag a marker: add a case with two `fields` where ONLY the second field carries the marker, and one with `action="flag"`; make sure the injected record is not removed by an earlier stage.

Keep every record matching at least one term so no score is exactly 0.0; scores are floats, keep them non-integer-valued.
