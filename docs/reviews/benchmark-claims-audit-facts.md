# contexel comparison claims: independent fact audit

Audited: 2026-11-26. The repository was read-only. Every experiment imported the harness with `python -B` from a separate scratch directory, so nothing was written to the repo.

Environment: Python 3.12.7, Windows 11 (AMD64). The installed versions match the recorded ones: toolz 1.1.0, langchain-core 1.4.9, llama-index-core 0.14.23, contexel 0.1.17. Also installed: langchain-community 0.3.27 and tiktoken 0.8.0.

Scratch scripts used as evidence (kept outside the repository): `deps.py`, `deps_linux.py`, `imp.py`, `probe_llama.py`, `alt.py`, `alt2.py`, `timed.py`, `tik.py`, `enc.py`.

## 0. Bottom line

* **The numbers reproduce.** Re-running the harness's own outcome code gave exactly the published rows:
  * toolz 100/100, 0 %, 91.62x;
  * langchain-core 30/30, 100 %, 0.52x, 89.7 %;
  * llama-index-core 100/100, 0 %, 129.21x, 74.2 %;
  * hand-written 93/32 and 97/97.

  The dependency counts (25 and 60) and the import medians also reproduce.
* **The interpretation of the competitor rows does not hold.** "Native ops" is computed, but only over step lists the author chose. Changing the wiring changes the competitor rows a lot, while the harness's own rule for "native" stays the same:
  * **toolz** goes from 2/6 to 4/6, and from 0 % to 100 % compliance, once its own `topk` and `accumulate` are used.
  * **langchain-core** goes from 30 % to 78 % "strong" recall once its input is in the order a strong-signal tool would return.
  * **llama-index-core** has native projection, dedupe and token-budget operations that the harness never wires in.
* **The "Compliance %" column is measured with contexel's own ~4 characters per token estimator.** In real `cl100k_base` tokens, contexel's contexts fit the 1,500 budget in only 6 % of episodes; langchain-core's fit in 79 %.
* **"Ships as a description" is outdated for both Anthropic and Cloudflare.**
* **ISON is recommended without saying that the same person authors both projects.**
* **Much is correct and honestly hedged:**
  * the determinism tests;
  * the `trim_messages`, `EmbeddingsRedundantFilter` and LlamaIndex-operand descriptions;
  * the absence of `context-engineering-toolkit` from PyPI (still absent today);
  * the concession that every timed library is deterministic;
  * the term-overlap baseline;
  * the stated limits on lexical matching and injection.

## 3. Must fix before the next release (ranked)

1. **F6 and S1: "Compliance 100 %" and "the only row with full marks".** In real cl100k tokens contexel fits the budget in 6 % of episodes, while langchain-core fits in 79 %. Rename the column to estimated compliance, or add a tiktoken column. This is the most damaging finding if a hostile reader finds it first.
2. **N1, N5, F1, F3 and N7: the toolz row.** 0 % compliance and 91.6x are wiring artifacts. With toolz's own `topk` and `accumulate`, under the harness's own native rule, it scores 4/6 and 100 % compliance; with the shared truncate glue added it equals hand-written (93/32).
3. **F2: langchain-core's "strong" recall of 30 %.** The harness never gives it strong-ordered input; with that input it scores 78 %. Fix the input order or label the column.
4. **N3, N4, F3 and F4: the LlamaIndex statements contradict each other.** "cover similar operations" against "0/6, serve none", and "not bounding them" is false. The 2.0 cutoff is a no-op under the strong signal. `excluded_llm_metadata_keys`, `IngestionPipeline` dedupe and `ChatMemoryBuffer`/`PromptHelper` are not wired. With `ChatMemoryBuffer`, llama scores 1/6, 30 % recall and 69 % compliance instead of 0/6 and 0 %.
5. **X5: Anthropic and Cloudflare "ship as a description".** Outdated: both ship the mechanism (`codemode` in the Agents SDK; Programmatic Tool Calling in beta), and Anthropic's post describes persisting code as Skills.
6. **I1: undisclosed common authorship of ISON.** Add one clause everywhere ISON is recommended. Also add compact JSON and CSV baselines to suite 6 (I3).
7. **C1: no statement that the benchmark is the library author's own.** Add it, with an invitation for corrections from maintainers.
8. **F5: "timing differences are the library's".** For llama-index the timing is entirely node conversion, with zero llama operations run.
9. **X7, X8 and X9: "semantic compressors" and "semantic rerankers".** ColBERT and cross-encoders are not compressors, LLMLingua is not a reranker, and only LLMLingua has a token budget.

## 4. Could be argued either way: the human decides

* **Whether `keyfilter(lambda ...)` or `accumulate` with a glue cost function counts as "native".** The harness already counts `keyfilter` with a lambda as native, so consistency argues yes. The opposite argument is that toolz has no token concept, so its budget is "really" glue.
* **Whether `LongContextReorder` counts as "rank".** It sorts by score, then interleaves: a score ordering, but not "descending by importance".
* **Whether wrapping records as chat messages is a fair use of `trim_messages` and `ChatMemoryBuffer`.** If it is fair for langchain-core, offer it to llama-index-core too. If it is not, langchain's 1/6 becomes 0/6.
* **Whether llama-index's content-hash dedupe through `IngestionPipeline` is "native dedupe" for a context-shaping task.** It runs at ingestion time and needs a docstore.
* **Whether `PromptHelper.truncate` counts as truncate and/or trim.** It shortens every chunk evenly to fit the window, rather than dropping low-ranked records.
* **Whether to keep the outcome experiment in its "own operations only" form.** The alternative is to replace or supplement it with an "expert configuration per library" run, ideally reviewed by each maintainer. The current form answers a legitimate but narrow question: what does each library do with zero glue.
* **Which deps figure to publish:** the transitive installed closure (25/60) or direct requirements (9/28). Both are true; the README must say which it uses.
* **Whether the hand-written baselines stand in for "model-improvised shaping".** They are reasonable stand-ins, but the drift premise itself is not measured (F9).
* **Whether to keep the time-stamped `context-engineering-toolkit` sentence at all.** It names an absent project on the strength of an unpublished citation.
