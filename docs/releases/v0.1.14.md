# Release record — contexel v0.1.14

- **Published:** 2026-07-26, via `.github/workflows/release.yml` on tag
  `v0.1.14` (commit `6e10b39`) — the first release through the full
  tag-gated path: suite on the tagged commit → tag↔version guard → build →
  `twine check` → publish → post-publish smoke. Run 30220744943: both jobs
  `success`.
- **The change that mattered:** deterministic set fingerprints in `dedupe`.
  Equal sets could previously fail to dedupe (set iteration order —
  insertion-history and hash-seed dependent — leaked into the fallback
  fingerprint). Sets/frozensets now fingerprint as sorted, type-qualified
  tuples. Found by CI on Python 3.10; also explains the earlier local
  one-off flake. v0.1.13 on PyPI carries the bug; v0.1.14 fixes it.
- **Pre-flight (local, real output):** 47 passed on `PYTHONHASHSEED` 0 and
  7; `twine check` PASSED for both artifacts.
- **Post-publish verification:** performed by the workflow's
  `post-publish-smoke` job — clean runner, `pip install contexel==0.1.14`
  from PyPI, quickstart executed. Conclusion: `success`.
- **Live metadata verified:** PyPI serves 0.1.14 (wheel + sdist); releases
  present: 0.1.13, 0.1.14.
- **Rollback story:** pin `contexel==0.1.13` (known set-dedupe bug) or yank
  0.1.14 on PyPI and patch forward. Never delete, never re-release a
  number.
